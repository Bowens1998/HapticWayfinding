## What the project is

A reproduction of the ICIC Lab (UF, Eric Jing Du) 2019 demo "Haptic suit for wayfinding". A participant in a VR headset stands in a glass booth. A walking figure ("little person") moves around them, and a haptic vest tells them which direction the figure is in, without seeing it.

Core spec (agreed with the user in the lab, 2026-11-18):
- bearing = signed horizontal angle between the participant's forward vector (HMD yaw) and the vector to the figure. 0 = front, +90 = right, ±180 = back.
- Quantise into 8 directions of 45°. Each direction drives the **two adjacent columns** (all 5 rows). Front = front-panel middle two columns. Front-left = front columns 1+2. Left = front left-most + back left-most. Back = back middle two.
- Implemented in `Scripts/Guidance/DirectionalHapticGuide.cs` (`GuidanceMode.AdjacentPair`) using `VestLayout.Ring` / `SectorNames`.

Hardware: HTC VIVE Pro (SteamVR, OpenXR; the Link Box needs Mini DisplayPort, not HDMI), bHaptics **Tactot** 40-motor vest via bHaptics Player 3.6.13 on Windows.

  - `Scenes/`, `Generated/`, `Rendering/` are **generated output**, committed so the project runs without regenerating.
- `tools/vest_test.py` — standalone vest test (`status | motors | columns | sweep | bearing <deg>`), needs `pip install websocket-client`.
- `tools/latency_test.ps1` — standalone test of whether vest delay builds up (3 beeps: baseline / after 60 s of fast changes / after 60 s idle).

## Build & run (Windows)

Unity path: `C:\Program Files\Unity\Hub\Editor\2022.3.62f3\Editor\Unity.exe`. Headless runs need Unity Hub **signed in** (otherwise "No valid Unity Editor license found").

```bash
# Full regenerate + bake + exe + preview stills (do NOT pass -nographics: baking and previews need the GPU)
HW_PREVIEW_DIR=<dir> "<Unity.exe>" -batchmode -projectPath HapticWayfindingVR \
  -executeMethod HapticWayfinding.EditorTools.PreviewCapture.FullBuildAndCapture -logFile <log> -quit

# Fast iteration: regenerate without baking + preview stills
... -executeMethod HapticWayfinding.EditorTools.PreviewCapture.FastBuildAndCapture ...

# Scene + bake + exe only
... -executeMethod HapticWayfinding.EditorTools.ProjectSetup.BuildAll ...
```

- Output exe: `HapticWayfindingVR/Builds/HapticWayfinding.exe` (git-ignored). Releases ship it zipped as `HapticWayfinding-win64.zip` without the `*_DoNotShip` folder.
- A build fails if the exe is running. Close the demo first.
- Grep the log for `error CS`, `[HapticWayfinding]` and `overlapping UVs`.
- The exe takes ~15–20 s to show its window. Without a headset it falls back to the desktop simulator.

## Pitfalls already hit (don't repeat)

- **Don't hand-edit the scene.** It is generated by `SceneBuilder`. Change builder or component defaults, then regenerate. The `.unity` file serialises old field values, so a changed default in a script does nothing until the scene is rebuilt.
- **Mesh cache**: `AssetFactory.BoxMesh` reuses `Generated/Meshes/box_WxHxD.asset` by size. If you change mesh or UV generation, delete `Generated/Meshes` first.
- **Lightmap vs. probes**: thin AND narrow boxes (min dim < 0.12 m and middle dim < 1.5 m) use light probes to avoid UV-overlap warnings. Floor, ceiling and walls must stay lightmapped. Wall-mounted thin pieces (door leaf, whiteboard) use `forceLightmap: true`, because probe lighting made them black.
- **Glass**: URP transparent with `_BlendModePreserveSpecular = 0` and very low alpha. Higher alpha or preserved specular makes the booth look like a grey veil from inside.
- **bHaptics latency**: the Player replaces frames with the same key and applies `turnOff` in ~1 ms. The bottleneck is **Bluetooth** to the vest: a high send rate makes delay pile up over minutes, then the vest disconnects. Keep `BHapticsWebSocketBackend` diff-only (send only changed keys; `turnOff` only keys that were on). Keep changes ≤ ~16 Hz (`minChangeInterval` 0.06 s) and refresh at 1 Hz with 3 s frames. Don't go back to fixed-rate streaming.
- The Player's status message (`ActiveKeys`) only lists keys from **the same WebSocket connection**, so a second probe connection cannot observe the demo's keys.
- The Player reports this vest as position `"Vest"`. Sending to `VestFront`/`VestBack` works (default). `F5` toggles 40-index `"Vest"` frames.
- Mapping: front device index 0 = wearer's **left** (verified in the lab). Back index 0 = wearer's left (assumed; verify with the `C` column test). Runtime flips F6/F7 are saved in PlayerPrefs (per machine).
- Automated keystrokes: `Start-Process -PassThru` often gives `MainWindowHandle = 0`. Look the window up via `Get-Process HapticWayfinding` and abort unless `GetForegroundWindow()` is the demo; otherwise keys land in another app.
- Lab laptop Bluetooth: the adapter had power-saving enabled and was shared with a BT mouse, keyboard and phone. Suspect this first when the vest lags or drops.
